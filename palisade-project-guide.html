Section 01

What you are building

A command-line launcher that starts a program with a restricted view of the kernel. You hand it a policy file and a command; it applies three independent restrictions and then executes.

usage
$ palisade run --policy policy/strict.toml -- python3 untrusted.py
# untrusted.py can read and write under /work, print to stdout,
# and nothing else. socket() returns EPERM. mount() kills it.

The three restrictions stack, and each one covers a gap the others leave open.

1
PR_SET_NO_NEW_PRIVS

A one-line prctl() that permanently blocks privilege gain through execve. Setuid binaries stop being setuid for this process and all its descendants. It is also the precondition that lets an unprivileged process install a seccomp filter at all.

2
seccomp-bpf

A BPF program attached to the process, consulted by the kernel on every syscall entry. It decides by syscall number and by scalar argument values. Verdicts: allow, return an errno, or kill. Fast — a few dozen nanoseconds — because it runs in kernel context with no context switch.

3
Landlock LSM

Filesystem access control by path, unprivileged and stackable. This exists because of the single most important constraint in the project, below.

The central constraint

A seccomp filter cannot dereference pointers. The BPF program sees the syscall number and the six raw register arguments. When those arguments are addresses — the path in openat, the sockaddr in connect — the filter sees a number, not a string. It cannot read userspace memory, because doing so safely would mean handling page faults inside the filter, and because another thread could rewrite that memory between the check and the syscall (a TOCTOU race).

This is why "block openat on /etc/passwd" is impossible in seccomp alone, and it is why Landlock exists. Understanding this trade-off is the intellectual core of the project — put it in the report.

What is deliberately out of scope

Linux offers a fourth mechanism, SECCOMP_RET_USER_NOTIF, which parks the syscall and asks a supervisor process for a verdict. The supervisor can read the target's memory and inspect real paths. It is the general solution, and it costs roughly a hundred times more per call because every check becomes a context-switch round trip.

At 30 lab hours it does not fit, and Landlock covers the filesystem case in-kernel for free. Do not build it. Do write a paragraph in the report explaining that you considered it and rejected it on cost grounds — a rejected design with a stated reason is stronger evidence of understanding than a half-finished feature.

Architecture mismatch — plan for it in week 1

Your VM is aarch64. The lab machine is x86_64. Syscall numbers differ between them — openat is 56 on ARM64 and 257 on x86_64. Hardcode a number and your sandbox will silently permit the wrong syscall when you move it, which is the worst possible failure for a security tool.

Two defences, both cheap. First, always name syscalls with SCMP_SYS(openat) and let libseccomp resolve them per-architecture. Second, add a GitHub Actions workflow running your tests on ubuntu-latest, which is x86_64 and free — you get continuous proof it works on demo hardware without borrowing a lab PC.

Section 07

First filter

Get this running in your first session. It proves the toolchain works and gives you the SIGSYS behaviour to reason about.

src/hello_filtered.c
#include <seccomp.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(void) {
    /* Default action for anything not explicitly allowed. */
    scmp_filter_ctx ctx = seccomp_init(SCMP_ACT_KILL_PROCESS);
    if (!ctx) { perror("seccomp_init"); return 1; }

    /* Allow write only to stdout and stderr — argument filtering
       works here because fd is a scalar, not a pointer. */
    seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 1,
                     SCMP_A0(SCMP_CMP_EQ, 1));
    seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 1,
                     SCMP_A0(SCMP_CMP_EQ, 2));

    /* Needed for a clean exit and for glibc's own teardown. */
    seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit_group), 0);
    seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit), 0);

    /* Dump the compiled filter as readable pseudocode — this is
       your debugger and a figure for the report. */
    seccomp_export_pfc(ctx, STDERR_FILENO);

    /* libseccomp sets PR_SET_NO_NEW_PRIVS for you here. */
    if (seccomp_load(ctx) < 0) { perror("seccomp_load"); return 1; }
    seccomp_release(ctx);

    write(1, "allowed: write to stdout\n", 25);

    /* Not in the allowlist. The kernel kills us here. */
    getpid();

    write(1, "never reached\n", 14);
    return 0;
}
expected behaviour
$ gcc -Wall -O2 -o hello hello_filtered.c -lseccomp
$ ./hello 2>/dev/null
allowed: write to stdout
Bad system call (core dumped)

$ echo $?
159                            # 128 + 31, where 31 is SIGSYS
Three things to notice

libseccomp sets no_new_privs automatically. The SCMP_FLTATR_CTL_NNP attribute defaults to on. You can turn it off, but you never should — without it an unprivileged seccomp_load fails outright.

Exit code 159 is your signature for a kill verdict. Your test suite will assert on it.

seccomp_export_pfc() is the single most useful debugging call in this project. It prints the compiled filter as readable pseudocode, turning "why was that blocked" from an hour of guessing into ten seconds of reading. Wire it behind a --dump-filter flag on day one.

Now try the same program with SCMP_ACT_ERRNO(EPERM) as the default instead of SCMP_ACT_KILL_PROCESS, and watch it limp along instead of dying. That contrast — fail-closed versus fail-soft — is a real policy design question and belongs in the report.

Section 08

Policy format

A policy is a text file, not a recompile. This is what makes the tool usable and what makes your demo interesting.

policy/script.toml
# Run a Python script with filesystem access limited to /work.

[meta]
name        = "python-script"
description = "CPython with read/write under /work, no network"

[seccomp]
# Anything not matched below.
default = "kill"          # kill | errno:EPERM | log

allow = [
  "read", "write", "openat", "close", "fstat", "newfstatat",
  "lseek", "mmap", "munmap", "mprotect", "brk",
  "rt_sigaction", "rt_sigprocmask", "getrandom",
  "exit", "exit_group", "futex", "getdents64",
]

# Refused politely — the program sees an error and may recover.
errno = [
  { syscall = "socket",  code = "EPERM" },
  { syscall = "connect", code = "EPERM" },
  { syscall = "ptrace",  code = "EPERM" },
]

[landlock]
read_write = ["/work"]
read_only  = ["/usr", "/lib", "/etc/ld.so.cache"]
execute    = ["/usr/bin/python3"]

How to discover the syscall set for a program

Do not guess. Trace it, then narrow.

building an allowlist empirically
$ strace -f -c -o trace.txt python3 hello.py
$ awk 'NR>3 {print $NF}' trace.txt | sort -u

This produces a working set, not a minimal one. Trim it by removing entries and re-running until something breaks — the syscalls whose removal breaks the program are the true minimum. Document that iteration in the report; it demonstrates the tension between security and usability better than any prose could.

Expect surprises

A trivial Python script needs on the order of 60 distinct syscalls, most of them from the dynamic loader before your code runs at all. A statically linked C program needs about six. That gap is a finding worth a paragraph.

Section 09

Policy loader

Keep C for enforcement and put parsing in Python. A Python script reads the TOML and emits a small generated C header or a simple binary spec; the C launcher consumes it. This avoids linking a TOML library into your security-critical code and keeps the C side auditable.

src/policy.c — the essential loop
int policy_apply(const policy_t *p) {
    uint32_t def = p->kill_default
        ? SCMP_ACT_KILL_PROCESS
        : SCMP_ACT_ERRNO(EPERM);

    scmp_filter_ctx ctx = seccomp_init(def);
    if (!ctx) return -1;

    /* Filter every thread, not just this one. Without TSYNC a
       multithreaded target escapes trivially: one thread installs
       the filter, the others run unrestricted. */
    if (seccomp_attr_set(ctx, SCMP_FLTATR_CTL_TSYNC, 1) < 0)
        goto fail;

    for (size_t i = 0; i < p->n_allow; i++) {
        int nr = seccomp_syscall_resolve_name(p->allow[i]);
        if (nr == __NR_SCMP_ERROR) {
            /* Unknown on THIS architecture — warn, do not fail.
               Some syscalls exist on x86_64 but not arm64. */
            warn_unknown(p->allow[i]);
            continue;
        }
        if (seccomp_rule_add(ctx, SCMP_ACT_ALLOW, nr, 0) < 0)
            goto fail;
    }

    for (size_t i = 0; i < p->n_errno; i++) {
        int nr = seccomp_syscall_resolve_name(p->errno_rules[i].name);
        if (nr == __NR_SCMP_ERROR) continue;
        if (seccomp_rule_add(ctx, SCMP_ACT_ERRNO(p->errno_rules[i].code),
                             nr, 0) < 0)
            goto fail;
    }

    if (p->dump) seccomp_export_pfc(ctx, STDERR_FILENO);

    int rc = seccomp_load(ctx);
    seccomp_release(ctx);
    return rc;

fail:
    seccomp_release(ctx);
    return -1;
}
Report material

The TSYNC flag is your CO3 hook. Write a two-thread demo where the filter is installed without TSYNC and the second thread happily calls a forbidden syscall. Then enable TSYNC and show it blocked. That is a synchronization bug with a security consequence, demonstrated in about forty lines.

Section 10

Landlock layer

There is no library. You call three syscalls through syscall(), and you must negotiate the ABI version because access rights added in later kernels cause EINVAL on older ones.

src/landlock.c
#include <linux/landlock.h>
#include <sys/syscall.h>
#include <sys/prctl.h>
#include <fcntl.h>
#include <unistd.h>

static inline int ll_create(const struct landlock_ruleset_attr *a,
                             size_t sz, uint32_t flags) {
    return syscall(__NR_landlock_create_ruleset, a, sz, flags);
}
static inline int ll_add(int fd, enum landlock_rule_type t,
                          const void *attr, uint32_t flags) {
    return syscall(__NR_landlock_add_rule, fd, t, attr, flags);
}
static inline int ll_restrict(int fd, uint32_t flags) {
    return syscall(__NR_landlock_restrict_self, fd, flags);
}

#define FS_READ  (LANDLOCK_ACCESS_FS_READ_FILE | \
                    LANDLOCK_ACCESS_FS_READ_DIR)
#define FS_WRITE (LANDLOCK_ACCESS_FS_WRITE_FILE | \
                    LANDLOCK_ACCESS_FS_MAKE_REG | \
                    LANDLOCK_ACCESS_FS_MAKE_DIR | \
                    LANDLOCK_ACCESS_FS_REMOVE_FILE | \
                    LANDLOCK_ACCESS_FS_REMOVE_DIR)

int landlock_apply(const policy_t *p) {
    int abi = ll_create(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION);
    if (abi < 1) return 0;   /* not available — seccomp still applies */

    struct landlock_ruleset_attr attr = {
        .handled_access_fs = FS_READ | FS_WRITE |
                             LANDLOCK_ACCESS_FS_EXECUTE |
                             LANDLOCK_ACCESS_FS_REFER |
                             LANDLOCK_ACCESS_FS_TRUNCATE,
    };

    /* Mask off rights the running kernel does not know about,
       newest first, falling through to older ABIs. */
    switch (abi) {
    case 1:
        attr.handled_access_fs &= ~LANDLOCK_ACCESS_FS_REFER;
        __attribute__((fallthrough));
    case 2:
        attr.handled_access_fs &= ~LANDLOCK_ACCESS_FS_TRUNCATE;
        __attribute__((fallthrough));
    default:
        break;
    }

    int rs = ll_create(&attr, sizeof(attr), 0);
    if (rs < 0) return -1;

    for (size_t i = 0; i < p->n_paths; i++) {
        struct landlock_path_beneath_attr pb = {
            .allowed_access = p->paths[i].rights & attr.handled_access_fs,
        };
        pb.parent_fd = open(p->paths[i].path, O_PATH | O_CLOEXEC);
        if (pb.parent_fd < 0) { close(rs); return -1; }
        int rc = ll_add(rs, LANDLOCK_RULE_PATH_BENEATH, &pb, 0);
        close(pb.parent_fd);
        if (rc) { close(rs); return -1; }
    }

    /* Required before restrict_self for unprivileged processes. */
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)) { close(rs); return -1; }

    int rc = ll_restrict(rs, 0);
    close(rs);
    return rc;
}
Why this closes the pointer gap

Landlock enforces on the resolved path inside the kernel's own path-walk, after symlinks are followed. A symlink in /work pointing at /etc/shadow is refused, because resolution and enforcement happen in the same place. There is no window for another thread to swap the path, so the TOCTOU race that defeats userspace path checking does not exist here. Make this the closing argument of your report.

Section 11

The launcher

Order matters, and getting it wrong produces a sandbox that silently does nothing.

src/main.c — the critical sequence
pid_t pid = fork();
if (pid == 0) {
    /* --- child: apply restrictions, then hand over --- */

    /* 1. Lock out privilege gain first. Everything else
          depends on this being set. */
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0))
        die("no_new_privs");

    /* 2. Filesystem restrictions before the syscall filter,
          because landlock_apply() itself needs open() and
          the landlock syscalls, which the filter may forbid. */
    if (landlock_apply(&pol))
        die("landlock");

    /* 3. Syscall filter last. From here on we are restricted. */
    if (policy_apply(&pol))
        die("seccomp");

    /* 4. Both restrictions survive execve and are inherited
          by every descendant. There is no way back out. */
    execvp(argv[optind], &argv[optind]);
    die("execvp");
}

/* --- parent: unrestricted, reports the verdict --- */
int status;
waitpid(pid, &status, 0);

if (WIFSIGNALED(status) && WTERMSIG(status) == SIGSYS)
    fprintf(stderr, "palisade: killed — forbidden syscall\n");
else if (WIFEXITED(status))
    fprintf(stderr, "palisade: exited %d\n", WEXITSTATUS(status));
The ordering trap

Install the seccomp filter before applying Landlock and your own Landlock setup gets blocked by your own filter. Symptom: landlock_create_ruleset returns EPERM, or the process dies with SIGSYS inside your setup code. Restrictions go from broadest to narrowest, and the filter is always last.

The parent staying unrestricted is deliberate — it is the only process that can still report what happened, and it demonstrates that seccomp is per-process, not global. That distinction is worth one sentence in the viva.

Section 13

Benchmarks

This section is what separates a good project from a working one. You are measuring the cost of security, which is exactly the trade-off analysis CO2 asks for.

Three configurations

  • Baseline — no filter
  • Small filter — allowlist of about 12 syscalls
  • Large filter — allowlist of about 70, as a Python policy needs
bench/syscall_loop.c — the measurement core
struct timespec t0, t1;
const long N = 5000000;

clock_gettime(CLOCK_MONOTONIC, &t0);
for (long i = 0; i < N; i++)
    syscall(SYS_getpid);          /* bypass glibc caching */
clock_gettime(CLOCK_MONOTONIC, &t1);

double ns = ((t1.tv_sec - t0.tv_sec) * 1e9 +
             (t1.tv_nsec - t0.tv_nsec)) / (double)N;
printf("%.1f ns/syscall\n", ns);
Two measurement traps

clock_gettime does not enter the kernel. It resolves through the vDSO, so it is never seen by your filter and never appears in strace. This is not a bug in your harness — it is a genuinely interesting fact, because it means a class of syscalls is entirely outside seccomp's reach. Put it in the report.

Call syscall(SYS_getpid) directly, not getpid(). Different glibc versions handle caching differently, and you want to measure the kernel boundary, not the library.

What you should find

ConfigurationPer syscallOverhead
No filter~ 65 ns—
12-rule filter~ 85 ns~ 30%
70-rule filter~ 110 ns~ 70%

Figures are indicative — your hardware will differ, and reporting your numbers is the point. What matters is the shape: cost grows with the number of rules, because libseccomp compiles the allowlist into a chain of comparisons on the syscall number.

The analysis that earns the marks

A syscall-loop microbenchmark is a worst case that no real program hits. Follow it with a macrobenchmark — time make on a small C project, or a pytest run, under each configuration. Overhead there will be in low single-digit percent, because real programs spend most of their time in userspace.

Then state the conclusion plainly: syscall filtering is essentially free for real workloads, and this is precisely why user notification is not. Your 30% microbenchmark overhead is a filter running in kernel context. A user-notification supervisor turns each intercepted call into a context-switch round trip measured in microseconds — three orders of magnitude worse. That is the quantitative justification for the design you chose, and it is the strongest paragraph in your report.

Run each configuration twenty times, report the median with interquartile range, and pin the process with taskset -c 2 to cut scheduler noise.

6:30The cost. One chart. Microbenchmark overhead versus macrobenchmark overhead, and the one-sentence conclusion.
7:30What you would build next. User notification, and the measured reason you did not.
Demo hygiene

Test on the actual lab machine architecture beforehand — see the CI note in section 03. Keep a recorded terminal session (asciinema) as a fallback if the lab environment misbehaves.

Section 16

Report structure

  1. CO mapping table — the one from section 02, on page one.
  2. Problem statement — running untrusted code, framed with a concrete case such as agent-generated scripts.
  3. Background — process isolation, the principle of least privilege, where seccomp and LSMs sit in the kernel. Cite Silberschatz chapter 17 and Love chapter 5.
  4. Design — the three layers, the ordering constraint, and why order matters.
  5. The pointer-dereference constraint — its own section. This is your central technical insight.
  6. Implementation — policy format, filter compilation, ABI negotiation, TSYNC.
  7. Evaluation — benchmark tables, the overhead chart, adversarial results.
  8. Rejected design: user notification — the mechanism, the measured cost argument, the conditions under which it would be worth it.
  9. Limitations — no network policy beyond blocking sockets outright, no resource limits (that is cgroups), vDSO calls invisible to the filter.
  10. References.

Sections 5 and 8 are where marks are won. Most submissions describe what they built; very few explain a constraint they hit and a design they rejected with numbers behind it.

Section 17

Troubleshooting

SymptomCause and fix
Exit code 159, no messageWorking as designed — SIGSYS from a kill verdict. Run under strace to see the last syscall attempted, then add it to the allowlist.
seccomp_load returns EACCESno_new_privs not set. libseccomp normally handles this; you have probably cleared SCMP_FLTATR_CTL_NNP.
landlock_create_ruleset returns ENOSYSKernel too old, or Landlock absent from the LSM list. Check /sys/kernel/security/lsm — see section 05.
landlock_create_ruleset returns EINVALYou requested an access right the running ABI does not support. Your ABI masking switch is wrong or missing.
Program dies before mainThe dynamic loader needs syscalls too — typically mmap, mprotect, openat, read, close, newfstatat. Build a static binary to isolate whether the problem is your program or ld.so.
Works in the VM, fails on the lab PCHardcoded syscall numbers. Grep your source for numeric literals and replace them with SCMP_SYS().
Second thread bypasses the filterMissing SCMP_FLTATR_CTL_TSYNC. Keep this reproducible — it is a demo, not just a bug.
strace shows nothing for a callIt resolved through the vDSO and never entered the kernel. Expected for clock_gettime, gettimeofday, getcpu.
Everything blocked despite a large allowlistRules added after seccomp_load, or added to a context you then released. Dump the filter with seccomp_export_pfc and read what actually compiled.
